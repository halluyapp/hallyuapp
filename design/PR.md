# Hallyu — Design Package v1 (for visual review)

> **Where Fandoms Meet.** A complete, coded design system and high-fidelity
> screen package for the next generation of Hallyu. **No production code is
> touched** — this is the design-review stage.

## What's in this PR

Everything lives under `/design`. It is self-contained and reproducible.

### 1. Design system (coded, token-driven)
- `src/css/tokens.css` — the single source of truth: color, type, spacing
  (4pt base), radius, elevation, motion, z-index, sizing. **Dark is primary;
  light is a fully supported first-class theme.**
- Brand: **Hallyu Iris `#7B61FF`** — a deliberate signal color chosen to avoid
  Netflix red / Spotify green / Twitch purple and the generic "AI app" look.
- Four world accents (K-Drama, C-Drama, Anime, Hollywood) used only as small
  metadata signals — architected so more worlds can be added with no redesign.
- `src/css/base.css`, `components.css`, `screens.css` — typography, layout
  primitives, the full component library, and screen compositions.
- 90+ stroke-based icons in `src/icons.py`.

### 2. Screens — all 17 product areas (64 coded screens)
Brand/entry, Onboarding, Home, Discover, Search, **universal Content Hub**,
Fandoms/Communities, Social Feed, Explore/Short-form, Creation, Profiles,
Notifications, Messages, Watchlist/Saved, Settings, Global States, Navigation —
including loading / empty / error / offline / success / toast / dialog / sheet
states, plus two **light-theme parity** renders.

### 3. High-fidelity PNG references
- `renders/screens/` — 64 screens at 780×1688 (390×844 @2×).
- `renders/pages/` — icon sheet, design-system sheet, component library,
  navigation map.
- `renders/contact-sheets/` — one sheet per product area, plus master sheets.

The PNGs are rendered *from the coded HTML* by `src/render.py`, so the
references **are** the coded design — not disconnected mockups.

### 4. Documentation
`README.md` plus `docs/`: design-system, screens, motion, navigation, assets,
mock-data.

## Why it's built this way
The whole package is generated by shared Python component helpers
(`src/ui.py`) that emit the same HTML for the component library page and every
screen. That guarantees **code/design parity** and makes the eventual port to
the Expo/React Native app a translation, not a re-imagining.

## How to rebuild
```bash
cd design
python3 src/build.py        # regenerate coded HTML
python3 src/render.py       # HTML -> PNG
python3 src/contact_sheet.py
```
